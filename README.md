# robinschmid.xyz

My personal website: a profile page, a daily **paper digest** (new arXiv papers and recent venue
papers that match my topics), and a **repo radar** (new and rising GitHub repositories).

It is a plain static site (no build step) on GitHub Pages. A GitHub Action runs every morning,
scrapes arXiv and GitHub as configured in [`digest.toml`](digest.toml), commits the JSON under
`site/data/`, and redeploys.

```
digest.toml              what to scrape: topics/keywords, venues, repo searches, AI summaries
site/                    the website (deployed as-is)
  index.html             profile: photo, name, links
  papers/  repos/        the two digest pages
  assets/                styles, scripts, profile photo
  data/                  generated by the scrapers; don't edit by hand
scripts/
  fetch_papers.py        arXiv → site/data/papers/
  fetch_repos.py         GitHub → site/data/repos/
  summarize.py           optional Claude relevance scores and summaries
state/llm_cache.json     so no paper is sent to Claude twice
.github/workflows/site.yml   daily update + deploy
```

## Change what gets scraped

Edit [`digest.toml`](digest.toml) and push. Topics, keywords, arXiv categories, venues, followed
authors, repo searches and watched GitHub orgs are all there. To refresh right away:
GitHub → Actions → **Update digests & deploy** → Run workflow (set *lookback* to backfill more days).

**Venues** come from arXiv too: a paper counts for CoRL if its author comment or journal
reference says so ("Accepted to CoRL 2026"). That covers most robotics and ML venues, but misses
papers that never go on arXiv.

## AI summaries (optional)

Without an API key, cards show the abstract's opening and papers are ranked by keyword score.
With one, Claude rates each candidate's relevance to the `interests` text in `digest.toml`, drops
the ones below `min_relevance`, and writes a two-sentence summary.

Add the key at GitHub → repo Settings → Secrets and variables → Actions → New repository secret,
name `ANTHROPIC_API_KEY`. About 40 new abstracts go to Claude per day, which comes to roughly
$0.10–0.30 per run with the default model and effort (a few dollars a month). The first run costs
more because it also rates the venue backlog. Rated papers are cached and never re-sent; set
`effort = "low"` or a cheaper `model` in `digest.toml` to spend less.

## Run locally

```sh
python3 -m http.server 8000 -d site          # preview at http://localhost:8000
python3 scripts/fetch_papers.py --lookback 7 # Python 3.11+, standard library only
GITHUB_TOKEN=$(gh auth token) python3 scripts/fetch_repos.py
```

## Deploy

1. Create a GitHub repo and push this directory to `main`.
2. Repo Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. The push deploys the site; the data refreshes daily at 06:30 UTC.

| A     | @     | 185.199.109.153 |
| A     | @     | 185.199.110.153 |

| AAAA  | @     | 2606:50c0:8002::153 |
| AAAA  | @     | 2606:50c0:8003::153 |
| CNAME | www   | `<github-user>.github.io` |

Remove any other A/AAAA records for `@` (for example the registrar's parking page). Then in the
repo: Settings → Pages → Custom domain → `robinschmid.xyz`, wait for the DNS check, and tick
**Enforce HTTPS**. Also verify the domain under your GitHub account Settings → Pages → Verified
domains, so no other repo can claim it.
